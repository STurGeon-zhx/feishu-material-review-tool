# 飞书客户素材审核工具

本项目使用飞书应用身份，把 JPG、PNG、MP4 导入可复用的客户审核电子表格。页面支持多个飞书应用账号、多个审核任务，以及同一任务下的多个自定义命名工作表；不需要个人 OAuth，也不需要机器人。

## 使用流程

1. 在页面添加飞书应用账号，填写账号名称、App ID 和 App Secret。凭证验证成功后，Secret 使用本机 AES-256-GCM 密钥加密保存。
2. 选择账号并创建任务，同时提前设置首个工作表名称。每个任务会创建独立的飞书电子表格。
3. 在任务内选择已有工作表，或创建新的命名工作表。一个任务的全部工作表共用同一文档和分享链接。
4. 选择素材并点击目标明确的导入按钮。批次在登记时固定目标工作表，页面状态变化不会把素材写到其他工作表。
5. 素材附件写入 A 列，B 列用于审核，C 列填写客户意见；D:I 是隐藏的幂等辅助列，首行固定。

素材编号和批次号在任务内持续递增。超过 20MB 的文件自动分片上传，单文件最大 2GB；写入失败可继续重试，已有成功项不会重复创建。

## 本地启动

环境要求：Node.js 24、npm，以及至少一个已发布的飞书企业自建应用。

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

打开 <http://localhost:3000>，在页面添加飞书应用账号。

默认配置：

```dotenv
DATABASE_URL=file:./data/poc.db
CREDENTIAL_KEY_PATH=./data/credentials.key
```

`data/credentials.key` 会在首次启动时自动生成并被 Git 忽略。已有旧版 `.env.local` 中的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 会在首次升级时导入为“默认飞书账号”；既有电子表格、工作表、素材行号、Token 和链接保持不变。旧 Base 只保留为历史归档。

## 飞书开发者后台配置

1. 创建普通企业自建应用，不添加机器人、网页应用、消息事件或 OAuth 回调。
2. 开通并发布应用身份权限：
   - 创建、读取、编辑和管理飞书电子表格；
   - 读取和写入工作簿结构、工作表结构及单元格；
   - 上传文件到云空间：`drive:drive`；
   - 查看云文档权限：`docs:permission.setting:read`；
   - 修改云文档权限：`docs:permission.setting:write_only`。
3. 若公开编辑设置失败，检查企业云文档对外分享策略。企业策略拒绝会标记为 `PARTIAL`，但不会阻止素材导入。

App Secret、访问令牌和文件内容不会返回前端或写入日志。App ID 创建后不可修改；更新 Secret 时，只有新凭证验证成功才会替换原值。

## 验证

```powershell
npm test
npm run typecheck
npm run build
```

真实验收建议使用两套应用凭证，分别创建任务；在其中一个任务创建两个工作表，确认任务间文档独立、同一任务工作表共享链接、切换后恢复上次选择，且两批素材写入各自登记时选定的工作表。

## 当前范围

- 本地单用户工具，无正式登录和管理员角色。
- 不支持个人 OAuth、机器人、任务删除/重命名、工作表删除/重命名。
- 不包含通知、回调、审核结果反向同步、素材删除同步、统计、AI、缩略图或云端部署。
