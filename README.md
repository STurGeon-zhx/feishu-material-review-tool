# 飞书客户素材审核 POC

本项目使用飞书应用身份把 JPG、PNG、MP4 持续导入同一个客户审核电子表格。使用者不需要绑定个人飞书账号，也不需要创建或使用 AI 机器人。

## 工作方式

1. 服务器通过 App ID 和 App Secret 获取 `tenant_access_token`。
2. 第一次点击“一键导入到审核表”时，应用自动创建“客户素材审核”电子表格、当天审核工作表和匿名可编辑链接。
3. JPG、PNG、MP4 逐文件上传；超过 20MB 自动使用分片上传，单文件最大 2GB。
4. 素材作为附件富文本写入 A 列，B 列提供审核下拉，C 列填写客户意见；辅助幂等字段隐藏在 D:I 列。
5. 同一天的后续批次追加到同一工作表，跨天按北京时间自动新建 `MMdd素材审核` 工作表；分享链接保持不变。
6. 每次最多写入 50 行，写后回读附件 token 和素材 UUID；响应不确定时先回查再重试，避免重复行。
7. “重建审核表”成功后才切换到新电子表格，旧电子表格、历史 Base 和旧链接不会被删除；当前批次未完成时会阻止重建。

## 本地启动

环境要求：Node.js 24、npm、一个已发布的飞书企业自建应用。

```powershell
npm install
Copy-Item .env.example .env.local
```

在 `.env.local` 填写：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
DATABASE_URL=file:./data/poc.db
```

启动应用：

```powershell
npm run dev
```

打开 <http://localhost:3000>。

## 飞书开发者后台配置

1. 创建普通“企业自建应用”。不添加机器人、网页应用、消息事件或 OAuth 回调。
2. 在“权限管理 → API 权限”中开通以下**应用身份**权限：
   - 创建、读取、编辑和管理飞书电子表格。
   - 使用 Sheet AI 工具读取和写入工作簿结构、工作表结构及单元格。
   - 上传文件到飞书云空间：`drive:drive`。
   - 查看云文档权限设置：`docs:permission.setting:read`
   - 修改云文档权限设置：`docs:permission.setting:write_only`
3. 创建并发布应用版本，使权限生效。
4. 如果匿名公开权限设置失败，在企业管理后台检查云文档对外分享策略。企业策略拒绝不会阻止素材导入，但验证结果会显示 `PARTIAL`。

App Secret 和访问令牌仅在服务端使用，不会返回浏览器或写入日志。

## 验证流程

1. 选择约 2MB JPG、小型 PNG、约 10MB MP4、约 50MB MP4、约 200MB MP4。
2. 点击“一键导入到审核表”，确认首次自动创建真实电子表格和当天工作表。
3. 打开审核表，确认 A 列附件可预览、B 列审核状态下拉和 C 列客户意见可编辑，D:I 辅助列已隐藏且首行冻结。
4. 同一天再导入第二批素材，确认仍写入原工作表且使用原链接。
5. 在无痕窗口验证匿名查看和编辑，并在验证区登记结果。
6. 通过日期集成测试确认跨天会新建工作表，不需要修改本机系统时间。
7. 按需测试“重建审核表”，确认新电子表格生效且旧电子表格与历史 Base 仍可访问。

## 开发验证

```powershell
npm test
npm run typecheck
npm run build
```

SQLite 文件、`.env.local`、上传临时文件和访问令牌不会提交到版本库。应用重启后，接收中或上传中的素材会恢复为可重试状态，已取得 `file_token` 的素材会继续写入电子表格。

匿名公开编辑可能被企业云文档策略禁止。此时素材导入仍可用，页面显示 `PARTIAL`；匿名查看失败或核心写入/回读失败则显示 `FAIL`。升级前创建的 Base 仅作为只读历史归档，不迁移、不删除，也不会再成为新导入目标。

当前依赖审计会报告 Drizzle ORM 的动态 SQL 标识符注入公告，且暂时没有可用修复版本。本项目不接受用户提供的 SQL 标识符；官方发布修复版本后应及时升级并重新审计。

## 当前范围

- 单一飞书企业共用一套应用凭证。
- 不包含跨企业商店应用、正式账号系统或管理员角色。
- 不包含通知、回调、审核结果反向同步、素材删除同步、统计、AI、缩略图和云端部署。
