# 飞书电子表格素材审核导入设计

## 1. 背景与目标

现有 POC 使用飞书多维表格承载素材审核数据。目标是将新导入链路整体切换为飞书电子表格，同时保留应用身份模式、固定分享链接、逐文件上传、失败重试和真实回读验证。

改造后不启用机器人能力，不使用用户 OAuth。服务端继续通过 `tenant_access_token` 调用飞书 OpenAPI。现有多维表格及其中的数据不迁移、不删除，仅作为历史归档保留。

## 2. 范围

### 2.1 包含

- 创建和维护一个活动的飞书电子表格工作簿。
- 按北京时间为每天创建一个素材审核工作表，同日导入继续追加。
- 上传 JPG、PNG、MP4 到飞书云空间，并将附件写入电子表格单元格。
- 配置审核下拉项、公开编辑权限、隐藏的幂等字段和固定分享链接。
- 对数据库进行非破坏性增量迁移。
- 保留现有批次、逐文件上传、失败重试、验证页和统一接口响应。
- 重建审核表时安全切换活动目标，保留所有旧资源。

### 2.2 不包含

- 迁移现有 Base 中的 14 条素材。
- 删除或修改历史 Base。
- 正式账号系统、用户 OAuth、机器人、通知或回调。
- 审核结果反向同步到本地数据库。
- 跨企业、多租户或云端部署。

## 3. 架构

保留现有 `TenantTokenProvider`、文件流接收、格式校验、临时文件清理、上传进度和批次 API。新增电子表格专用组件，与历史 Base 逻辑隔离：

- `FeishuSheetsService`：封装工作簿、工作表、单元格、数据验证、样式和回读相关 OpenAPI。
- `SpreadsheetSetup`：创建工作簿，配置初始工作表和公开权限，保存稳定链接。
- `DailySheetManager`：按北京时间查找或创建当天工作表，配置表头、列宽、冻结、隐藏列和审核下拉项。
- `DriveAttachmentUploader`：将普通上传和分片上传统一为附件 token 输出。
- `SheetBatchFinalizer`：按 UUID 幂等检查、追加行、写入附件和元数据、回读确认。

现有 Base 服务暂不删除，但新的活动目标选择、上传和 finalize 链路不得调用 Base 写入接口。

## 4. 电子表格布局

活动工作簿名称为“客户素材审核”。每天使用一个工作表：默认名称为 `MMdd素材审核`，例如 `0821素材审核`。如果跨年发生同名冲突，则使用 `yyyyMMdd素材审核`。

同一天的多次导入追加到同一工作表；日期切换以 `Asia/Shanghai` 为准。

| 列 | 名称 | 可见性 | 内容 |
| --- | --- | --- | --- |
| A | 素材 | 显示 | 附件富文本，显示原文件名并支持点击预览 |
| B | 审核 | 显示 | 下拉选项，默认“待审核” |
| C | 客户意见 | 显示 | 客户自由填写文本 |
| D | 素材编号 | 隐藏 | 工作簿内连续编号 `001`、`002` |
| E | 批次 | 隐藏 | `第 N 批` |
| F | 素材UUID | 隐藏 | 系统生成的稳定幂等键 |
| G | 类型 | 隐藏 | `图片`或`视频` |
| H | 文件Token | 隐藏 | 飞书附件 token |
| I | 上传时间 | 隐藏 | 上传完成时间 |

审核下拉值为“待审核”“审核通过”“需修改”，分别使用中性、通过和警告颜色。第一行冻结；A、C 列加宽，B 列居中；数据行使用统一高度；D 至 I 列隐藏。

## 5. 数据模型

数据库使用非破坏性增量迁移。

### 5.1 `projects`

新增可空字段：

- `resource_type`：`base` 或 `sheet`，已有记录默认视为 `base`。
- `spreadsheet_token`：飞书电子表格 token。
- `spreadsheet_url`：稳定分享链接。

原有 `app_token`、`table_id`、Base 分享链接和创建状态字段全部保留。

### 5.2 `sheet_tabs`

新增表：

- `id`
- `project_id`
- `local_date`
- `sheet_id`
- `sheet_name`
- `next_row`
- `setup_status`
- `setup_error`
- `created_at`
- `updated_at`

`project_id + local_date` 建立唯一约束。

### 5.3 `assets`

新增可空字段：

- `sheet_id`
- `sheet_row_number`

原有 `record_id` 保留，仅用于历史 Base 记录。附件 token 继续复用现有 `file_token` 字段。

活动目标只能从 `resource_type=sheet` 且状态为 `ready` 或 `partial` 的项目中选择。旧 Base 不再接收新批次。

## 6. 目标表创建与重建

`POST /api/destination/ensure` 使用 `Idempotency-Key`：

1. 查询活动电子表格；存在则直接返回。
2. 创建新的项目草稿，类型为 `sheet`。
3. 使用应用身份创建电子表格工作簿。
4. 将默认工作表配置为当天工作表，或创建当天工作表后保留平台允许保留的默认表。
5. 设置表头、列宽、行高、冻结、隐藏列和审核下拉项。
6. 设置 `external_access=true` 和 `anyone_editable`。
7. 回读工作簿、工作表和公开权限。
8. 保存 `spreadsheet_token`、分享链接、实际权限和创建状态。

如果公开编辑被企业策略拒绝，但工作簿和工作表可正常使用，则状态为 `partial`。其他设置失败不得成为活动目标。

`POST /api/destination/rebuild` 创建新工作簿。只有创建、布局、回读和权限配置达到 `ready` 或允许的 `partial` 后才切换活动目标。旧 Base 和旧电子表格永不自动删除。

## 7. 导入数据流

1. 页面调用 `destination/ensure`。
2. `DailySheetManager` 确保当天工作表存在并完成配置。
3. 创建批次，为工作簿分配连续的批次号和素材编号。
4. 前端逐文件调用内容上传接口。
5. 服务端把原始流写入临时文件，使用文件特征校验 JPEG、PNG、MP4，并执行 2GB 限制。
6. `DriveAttachmentUploader` 上传文件：小文件走普通上传，大文件走 prepare、part、finish 分片上传。
7. 成功后保存附件 token；请求结束始终清理临时文件。
8. finalize 读取目标工作表的 UUID 列，过滤已经存在的素材。
9. 获取飞书实际数据末行，在单工作表互斥锁内分配追加范围。
10. 分块写入 A 至 I 列：附件、默认审核状态、空客户意见和隐藏元数据。
11. 回读 UUID、附件 token 和审核状态，确认真实写入结果。
12. 保存实际 `sheet_id` 和最近一次发现的行号。

电子表格写入不沿用 Base 的 200 条记录上限。使用内部固定分块大小串行写入，具体大小在实现期根据飞书 Sheets 请求限制确定并通过测试固定。

## 8. 幂等与并发

素材 UUID 是电子表格链路的稳定主键。行号仅作为最近一次写入证据，不能作为重试主键，因为客户可能排序、插行或移动数据。

- finalize 前读取 UUID 列，已存在的 UUID 不重复写入。
- 写入响应不确定时先回读 UUID；找到后再校验对应附件 token。
- 确认 UUID 不存在后才允许重试写入。
- 已取得附件 token 的素材不得重复上传。
- 同一工作表的行分配和写入通过进程内 keyed mutex 串行化。
- `next_row` 只是缓存；每次 finalize 仍以飞书实际数据末行为准。
- 应用重启后把 `receiving`、`uploading` 恢复为可重试状态；已有附件 token 的素材直接继续写表。

POC 只运行单个应用进程，因此不引入分布式锁。

## 9. API 与页面

保持现有 API 路径，降低前端改动：

- `GET /api/destination`
- `POST /api/destination/ensure`
- `POST /api/destination/rebuild`
- `POST /api/destination/retry`
- `POST /api/projects/:id/batches`
- `PUT /api/projects/:id/assets/:assetId/content`
- `POST /api/projects/:id/batches/:batchId/finalize`

目标表接口返回资源类型、名称、分享链接、状态、请求权限、实际权限、素材数量和当前日期工作表名称。不得向前端返回 App Secret 或访问令牌。

页面将 Base 相关文案替换为“电子表格”，保留应用身份状态、打开/复制链接、重建、拖拽文件、逐文件进度、失败重试和验证区。主按钮仍为“一键导入到审核表”。不增加登录、OAuth、机器人或项目管理入口。

## 10. 错误处理

- 上传成功、写表失败：保留附件 token，仅重试写表。
- 部分行写入成功：回读 UUID 确认成功项，只重试缺失项。
- 公开编辑被企业策略拒绝：不重试，目标状态为 `partial`。
- 工作簿或布局创建失败：保存失败步骤，不切换活动目标。
- 重建失败：继续使用旧活动电子表格。
- 网络错误、429 和 5xx：指数退避，最多三次。
- 参数、权限和企业策略错误：标记不可重试并展示可操作信息。
- 日志只记录步骤、请求 ID 和错误码，不记录 App Secret、访问令牌或文件内容。

## 11. 验证与测试

### 11.1 单元测试

- 日期工作表命名、同日复用、跨日创建和跨年冲突。
- 素材编号、批次编号和 UUID 幂等回查。
- 行分配互斥、真实末行优先和分块写入。
- 普通/分片上传边界、2GB 限制和文件类型校验。
- 部分写入恢复、重建失败保留旧目标。
- 旧 Base 项目不被选为活动目标。

### 11.2 接口与页面测试

- 首次创建、重复 ensure、日期工作表创建和同日追加。
- 上传成功但写表失败、响应不确定回查、应用重启恢复。
- 策略拒绝后的 `partial` 和重建安全切换。
- 页面不存在 OAuth/机器人入口，进度、重试、复制链接和验证状态正确。

### 11.3 真实验收

使用 JPG、PNG、小于 20MB MP4、约 50MB MP4 和约 200MB MP4 完成至少两批真实导入，并确认：

- 第一批自动创建电子表格和当天工作表。
- 附件名称可见，文件可以点击预览。
- 审核下拉和客户意见可编辑。
- 第二批继续写入同一工作簿，公开链接不变。
- 同日追加到同一工作表，跨日新建工作表。
- 无用户 OAuth、无机器人能力。
- 原 Base 和原有数据保持不变。
- 所有自动验证项均来自真实 OpenAPI 回读，不能仅根据写请求成功点亮。

匿名编辑被企业策略禁止时，总体结果为 `PARTIAL`；核心创建、上传、写入或附件回读失败时为 `FAIL`；全部自动和人工验证通过时为 `PASS`。

## 12. 安全与约束

- 仅支持一个飞书企业和一套应用凭证。
- `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 仅存在服务端环境变量。
- 访问令牌只保存在内存缓存，不写入数据库、前端响应或日志。
- 临时文件在请求结束时清理。
- 公开编辑链接意味着持有链接的人可以修改表格，页面需要明确提示该风险。
- 运行时只使用飞书 OpenAPI，不依赖 `lark-cli`。
